# Telegram-бот: парсер вакансий

Один проект — два независимых продукта:

| Продукт | Что делает | Точка входа |
|---------|------------|-------------|
| **Канал** [@prdsvac](https://t.me/prdsvac) | ежедневный дайджест вакансий продуктового дизайнера | `python -m bot.run_once fetch` |
| **Подписки** | личные дайджесты в ЛС по выбранным ролям | `python -m bot.run_once subscribers` |
| **Чат-бот** | UI подписки: выбор ролей, отписка; админка `/stats` и `/users` | `python -m bot.chat_main` |

Публикуются только вакансии, появившиеся за последние **72 часа** (`MAX_VACANCY_AGE_HOURS`).
Прод крутится на reg.ru (ISPmanager): канал в 10:00 МСК, рассылка подписчикам в 10:02.

## Источники

| Площадка | Покрытие |
|----------|----------|
| **HeadHunter (hh.ru)** | Россия, Беларусь, Казахстан, Узбекистан, Кыргызстан, Армения, Азербайджан, Молдова, Грузия, Таджикистан + прямой поиск по 11 работодателям бигтеха |
| **Карьерные сайты** | `rabota.sber.ru` (HTML-парсинг) — только канал. Подписки сайт Сбера не опрашивают: вакансии там подгружает скрипт, парсер их не видит, а вакансии Сбера и так приходят с HH |
| **Хабр Карьера** | Только подписки. Вся лента IT-вакансий за 72 ч (~700, 14 запросов) раз за прогон, роли отбирают свои по названию. Открытый JSON без ключа |
| **Himalayas, We Work Remotely, Jobicy** | Удалёнка по миру — только подписки с регионом «мир» или «оба». Берём только вакансии без ограничения по стране (`worldwide=true`, «Anywhere in the World», `geo=anywhere`) и выкидываем названия с регионом («LatAm Only», «US») и подработки по разметке ИИ. За 72 ч ~25–30 вакансий на все роли. Indeed и LinkedIn не подключены: открытого API нет, сайты блокируют ботов |
| **GeekJob** | Весь каталог (~270 вакансий, 3 страницы) раз за прогон, роли отбирают свои по названию. Поиск сайта не используем: `search` он игнорирует, `qs` отдаёт часть каталога по релевантности |
| **GetMatch** | Вся лента (`language=ru`) раз за прогон, для всех ролей. Фильтр `specialization` сайт игнорирует — отдаёт все IT-вакансии |

## Регион поиска

Первый шаг /start — где искать: «СНГ», «Удалёнка по миру» или «СНГ + удалёнка
по миру» (`bot/regions.py`, таблица `user_region`). Регион общий для всех ролей.
Кто не выбирал — СНГ, поэтому подписчики до 24.10.2026 получают то же, что и
раньше. Сбор общий, регион решает только, какие площадки идут человеку; шапка
подборки перечисляет площадки его региона.

## Роли

Подписчик выбирает специальность, затем одну или несколько вакансий внутри неё
(`bot/role_categories.py`, `bot/roles.py`):

| Специальность | Вакансии |
|---------------|----------|
| Дизайн | UX/UI \| Продуктовый дизайнер, Коммуникационный дизайнер, Графический дизайнер, Арт-директор |
| Frontend | React, Vue, Angular |
| Backend | Python, Java, Go, PHP, C# / .NET |
| Fullstack | Fullstack |
| Mobile | Flutter, iOS, Android, React Native |
| Продукт | Product Manager, Product Owner |
| QA | Ручное тестирование, Автоматизация |
| Data | Data Scientist, ML / AI Engineer, Data Engineer, Аналитик данных / BI, Продуктовый аналитик, Data Governance |
| Руководители | Head of Data / CDO, Head of AI, Head of Design, Head of Product / CPO, CTO / Head of Engineering |

В **канал** уходит только `product_designer` — фильтр `bot/filters.py`, он отсекает
аналитиков, менеджеров, motion/графику и смежные роли. Для остальных ролей —
regex-фильтры в `bot/role_filters.py`.

Для ролей, где по названию не видно отрасли («Тестировщик», «Руководитель
проектов» одинаково частые в IT, на стройке и на производстве), дополнительно
задан `hh_professional_roles` — профобласть в поиске HH.

Выбор ролей не хранит состояние: категория едет в `callback_data` кнопки, а
отмеченные вакансии читаются из галочек самой клавиатуры. Поэтому перезапуск
`chat_main` не ломает уже открытые у пользователей клавиатуры.

## Локальный запуск

```bash
cd "/Users/vladislavkotyrev/Desktop/тг бот парсер вакансий"
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Отредактируйте `.env`:

```env
TELEGRAM_BOT_TOKEN=ваш_токен
TELEGRAM_CHAT_ID=-1001234567890
TELEGRAM_ADMIN_ID=ваш_telegram_id
HH_USER_AGENT=ProductDesignerVacancyBot/1.0 (your@email.com)
HH_ACCESS_TOKEN=
TIMEZONE=Europe/Moscow
MAX_VACANCY_AGE_HOURS=72
```

> **HH.ru API:** обязателен корректный `User-Agent` с контактным email. Если анонимные
> запросы получают `403` — зарегистрируйте приложение на [dev.hh.ru](https://dev.hh.ru/admin)
> и добавьте `HH_ACCESS_TOKEN` ([документация](https://github.com/hhru/api)).

Режимы `bot.run_once`:

```bash
python -m bot.run_once fetch                # спарсить и опубликовать в канал
python -m bot.run_once subscribers          # разослать дайджесты подписчикам
python -m bot.run_once subscribers-preview  # что ушло бы подписчикам, без отправки
python -m bot.run_once test                 # тестовый пост в канал на моках
python -m bot.run_once status               # статистика последнего прогона
python -m bot.run_once broadcast --file broadcasts/<id>.html          # превью разовой рассылки только админу
python -m bot.run_once broadcast --file broadcasts/<id>.html --send   # разослать подписчикам
```

Чат-бот подписок (polling, держит один процесс через pid-lock в `logs/chat-bot.pid`):

```bash
python -m bot.chat_main
```

> Одновременно с ботом нельзя запускать второй polling-процесс на том же токене —
> Telegram отдаёт `getUpdates` только одному потребителю.

## Деплой

Прод — reg.ru / ISPmanager: **[deploy/isp/README.md](deploy/isp/README.md)** (cron,
watchdog, автодеплой).

Путь изменения: push в `main` → GitHub Actions гоняет тесты на Python 3.8
(`.github/workflows/tests.yml`) → сервер раз в 5 минут сам забирает коммит с
зелёными тестами (`deploy/isp/autodeploy.sh`), проверяет запуск, при сбое
откатывает и пишет админу в Телеграм. Ключей и паролей от сервера в GitHub нет.
Проверить скрипт автодеплоя без сервера: `bash scripts/test_autodeploy.sh`.

## Команды чат-бота

Основной UI — кнопки меню внизу чата: «Мои вакансии», «Прекратить рассылку»,
«Выбрать роли». Команды оставлены как fallback:

| Команда | Описание |
|---------|----------|
| `/start` | Приветствие и запуск выбора ролей |
| `/myrole` | Текущая подписка |
| `/stop` | Отписаться |
| `/stats` | DAU/MAU, охват рассылкой, приток и отток, плюс подписчики, рассылка и канал — только для `TELEGRAM_ADMIN_ID` |
| `/users` | Кто пользуется ботом: имя, @username, роли, дата подписки, последняя активность — только для админа |

Пользователь **обязан** написать `/start` первым — иначе Telegram не даст боту
писать ему в личку.

## Как работает дедупликация

Три слоя, чтобы одна вакансия не ушла дважды:

1. `uid = source:external_id` — точное совпадение внутри площадки.
2. `dedup_key` — нормализованные `название|компания`, ловит кросс-площадочные дубли.
   При конфликте побеждает источник с более высоким приоритетом (`source_priority.py`).
3. Раздельные хранилища: канал помнит опубликованное в таблице `vacancies`,
   подписчики — в `subscriber_sent` (по каждому пользователю отдельно).

В `vacancies` пишутся **только опубликованные** вакансии. Иначе вакансия, впервые
увиденная без даты публикации, навсегда блокировала бы себя по `dedup_key`.

## Поведение рассылок

- **Канал:** если новых вакансий нет — всё равно уходит уведомление «новых нет».
- **Подписчики:** если новых нет — уходит «Новых вакансий … нет», не чаще раза
  в день. Если хоть одна роль подписчика не собралась (сбой, ограничение HH),
  молчим: честно сказать «нет» нельзя.
- Повторный ручной `subscribers` в тот же день безопасен: уже отправленные
  вакансии и уже ушедшее «новых нет» повторно не придут.
- В один дайджест — не больше 30 самых свежих вакансий. Под ним кнопка
  «Показать остальные N»: по нажатию бот присылает остаток, один раз. Кто не
  нажал, получит остаток в следующие дни, пока вакансиям меньше 72 часов.
- Длинные дайджесты автоматически делятся на несколько сообщений Telegram.
- Одна вакансия с разных площадок приходит один раз: кроме точного совпадения
  названия и компании, бот склеивает разное написание («RWB» и «RWB (Wildberries
  & Russ)», «медиа сервисов» и «медиасервисов»). Грейд при этом учитывается.
- При смене ролей история доставок сохраняется — уже присланные вакансии не
  придут снова.
