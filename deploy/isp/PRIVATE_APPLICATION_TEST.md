# Личный тест откликов

Тест включается только для положительного `TELEGRAM_ADMIN_ID` и только в его личном чате. Публичное меню не меняется. Вход: `/try_apply` или `/start apply_test`. Выход: `/exit_test`.

Доступны два входа: по должности (резюме требуется при первом отклике) и по резюме (текст, PDF, TXT или DOCX → проверка профиля → подборка). Вакансии, разбор профиля и письма демонстрационные, без LLM. На HH ничего не отправляется. PDF читается локально: до 2 МБ и 20 страниц, без пароля, с текстовым слоем. Сканам нужен OCR, который пока не подключён. Обработка PDF ограничена по времени и памяти и выполняется в отдельном процессе; файл и извлечённый текст не записываются на диск. Данные сессии находятся в памяти не более 30 минут; выход и перезапуск их удаляют. Сообщения остаются в самом Telegram.

## Временная установка на текущий сервер

Используйте проверенные `scripts/private_application_test.py`, `bot/application_demo.py` и `bot/application_demo_pdf.py` из одного зафиксированного коммита отдельной ветки. Python 3.8 поддерживает закреплённый `pypdf==5.9.0`. Из каталога действующего бота:

```sh
.venv/bin/python -m pip install 'pypdf==5.9.0'
.venv/bin/python /path/private_application_test.py install --module-file /path/application_demo.py --pdf-module-file /path/application_demo_pdf.py
```

Installer проверяет текущую версию Python и модуль до изменения файлов, сохраняет резервную копию, добавляет точечный hook в фактический серверный `chat_main.py`, включает единственный флаг в `.env` и перезапускает тот же процесс. Ветку и коммиты сервера не меняет. На время теста guard приостанавливает автодеплой; watchdog и cron рассылок остаются настроенными как прежде.

Копия хранится в `logs/private-application-test-backup` (доступ только владельцу), marker — `logs/private-application-test.active`. Результат PID/lock подтверждает запуск процесса; дополнительно проверьте ответ бота на `/try_apply` и отсутствие polling Conflict в свежем логе. Не запускайте второй polling с тем же токеном.

## Обновление уже установленного теста

После установки той же зависимости выполните новую версию installer:

```sh
.venv/bin/python /path/private_application_test.py upgrade --module-file /path/application_demo.py --pdf-module-file /path/application_demo_pdf.py
```

Обновление сверяет хеши установленной версии, проверяет оба новых модуля и извлечение текста из тестового PDF отдельным worker до остановки процесса и сохраняет исходную резервную копию. Worker загружает библиотеку до установки лимитов, затем на Linux получает до 256 МиБ дополнительного виртуального адресного пространства с учётом системного hard limit. Меняются только два файла демо и их хеши в manifest. Для последующего отката используйте эту новую версию installer: она учитывает добавленный PDF-модуль. Перезапуск сбрасывает текущую тестовую сессию: откройте `/try_apply` и отправьте PDF ещё раз.

## Завершение тестирования и откат

`/exit_test` очищает сессию пользователя. Для удаления временной функции и возобновления автодеплоя выполните из каталога бота:

```sh
.venv/bin/python /path/private_application_test.py rollback
```

Откат сначала сверяет хеши изменённых файлов. При чужих правках он останавливается, чтобы не затереть их. Резервная копия сохраняется. Ключи и содержимое резюме installer не выводит.
