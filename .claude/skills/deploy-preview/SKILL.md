# Превью изменений перед деплоем

Владелец решает, выкатывать ли изменение, по тому, что увидят люди в Телеграме,
а не по диффу. Поэтому перед push в `main` покажи ему превью «сейчас → после
деплоя» и дождись явного «ок». Push в `main` — это и есть деплой: сервер
забирает зелёные коммиты сам или по ручному `git pull`.

## Шаги

1. **Узнай базу — что сейчас на сервере.** Обычно это `origin/main` (если ты
   ещё не пушил). Если владелец присылал вывод `git log -1` с сервера — бери
   этот коммит. Не уверен — сравнивай с `origin/main` и напиши, с чем сравнил.

2. **Проверь, что сцены покрывают изменение.** Сцены — функции с `@scene` в
   `scripts/preview_bot.py`: «Готово» после подписки, «Мои вакансии», `/level`,
   утренняя подборка, `/stats`. Если изменение трогает экран, которого там нет
   (новая команда, новый шаг, рассылка), — добавь сцену. Правила сцены:
   - экран строит настоящий код бота (хэндлер, форматтер, `SubscriberService`)
     на тестовых данных; текст руками не пиши — превью должно ловить ошибки кода;
   - сцена должна запускаться и на старой версии: новое проверяй через
     `hasattr`/`getattr`, а если упадёт — превью покажет «нет в этой версии»;
   - сеть не трогать: сбор вакансий подменяется `mock.patch` (см. сцену `digest`).

3. **Собери превью** (нужны зависимости бота: `pip install -r requirements.txt`):
   ```bash
   python scripts/preview_bot.py --base <база> --out <scratchpad>/preview.html
   ```
   Скрипт сам поднимет базовую версию во временном `git worktree`, прогонит
   сцены на обеих версиях и напишет, сколько сцен изменилось.

4. **Посмотри превью сам до того, как показывать.** Один скриншот
   (Playwright, `fullPage: true`). Ищи: сцену «пропало», которую ты не убирал;
   изменения в сценах, которые не должны были меняться; обрезанный текст,
   лишние строки, опечатки. Нашёл — исправь код и собери заново.

5. **Покажи владельцу.** Опубликуй HTML через Artifact (тот же файл —
   та же ссылка при повторной сборке) и в ответе перечисли по-человечески,
   что изменится для пользователей и что не изменится. Сцены «без изменений»
   — подтверждение, что остальное не задето; упомяни это.

6. **Жди «ок».** Без явного согласия в `main` не пушь. Правки после
   замечаний — снова шаги 3–5.

## Чего не делать

- Не рассылать ченжлоги и сообщения подписчикам: владелец против, люди
  отписываются. Превью — только для владельца.
- Не трогать канал (`service.py`, `run_once fetch`, `bot/grades.py`,
  `bot/formatters.py` в части постов канала) без прямой просьбы.
