# Showtime для роликов бота

Локальная интеграция [mishanaer/showtime](https://github.com/mishanaer/showtime), закреплённая на commit `2bd4b44fcf47f9802233c4b6e33be61096b36428`. Из готовой записи интерфейса делает MP4 с рамкой телефона, фоном и индикаторами нажатий. Исходники Showtime остаются в отдельной checkout: в репозитории бота хранится только эта обвязка.

В бота, серверный деплой и рассылку интеграция не включена. Она не использует токены, не вызывает ИИ и ничего не отправляет пользователям.

## Установка

Нужны Python 3.12, Git, FFmpeg и ffprobe в `PATH`. Xcode и iOS Simulator для импорта готового видео не нужны. Зависимости видео устанавливаются отдельно от окружения бота.

Из корня репозитория:

```bash
git clone https://github.com/mishanaer/showtime.git ../showtime-upstream
git -C ../showtime-upstream checkout --detach 2bd4b44fcf47f9802233c4b6e33be61096b36428
python3.12 -m venv ../showtime-venv
../showtime-venv/bin/python -m pip install -r motion/showtime/requirements.txt
../showtime-venv/bin/python ../showtime-upstream/scripts/showtime_doctor.py
```

Doctor должен вернуть `"ok": true`. Если FFmpeg отсутствует, установите его отдельно; например, через официальный Homebrew-пакет `ffmpeg`. Обвязка сама не скачивает исполняемые файлы и не изменяет системные настройки.

## Входные файлы

1. Запись интерфейса в MP4 продолжительностью от 10 секунд. Для рамки телефона нужна портретная запись всего экрана без уже нарисованной рамки, например 402×874 или кратный размер. Несовпадение пропорций более чем на 1% останавливает экспорт до создания файлов. Старый проморолик с рамкой и заголовками не годится: повторное вложение в телефон обрежет изображение.
2. JSON с моментами фактических нажатий в секундах и координатами в исходной записи. Координаты должны соответствовать `coordinate_space`; их отношение сторон должно совпадать с записью. Пример структуры:

```json
{
  "coordinate_space": {"width": 402, "height": 874},
  "events": [
    {"id": "apply", "type": "tap", "time": 2.0, "x": 200, "y": 700}
  ]
}
```

Числа выше иллюстративные: замените их измеренными моментами и координатами. Первый тап должен быть не раньше 25/60 секунды; после последнего нужно оставить время на затухание индикатора. Удержания поддерживаются через `type: "long_press"` и `hold_seconds`. Индикаторы свайпов не поддерживаются. Для записи без нажатий передайте `[]`; для записи с нажатиями нельзя подменять журнал пустым списком.

Для записи HTML-прототипа явно обозначайте, что это прототип: импорт видео не превращает его в запись работающего Telegram-клиента. Не подменяйте запись рисунком похожего интерфейса.

## Рендер

Из корня репозитория, заменив пути на свои:

```bash
../showtime-venv/bin/python motion/showtime/render.py \
  --showtime-root ../showtime-upstream \
  --capture /absolute/path/capture.mp4 \
  --events /absolute/path/events.json \
  --output motion/showtime/outputs/applications-v1.mp4 \
  --layout full
```

`full` показывает телефон целиком. `crop-top` и `crop-bottom` увеличивают соответствующую часть; экспорт остановится, если заданные нажатия выпадут за видимую область.

Результат: MP4, `.quality.json`, `.render.json` и папка `.showtime` с абсолютными путями к исходным assets и рабочими слоями. Существующий результат не перезаписывается — для новой версии задайте новое имя. Обвязка отказывается запускать другую версию Showtime или изменённые upstream scripts/assets.

Техническая проверка выполняется до завершения команды. Затем просмотрите весь ролик несколько раз: читабельность, полный результат действия, плавность переходов, совпадение индикаторов с нажатиями, конец и начало петли. Автоматическая проверка cadence этого не подтверждает.

## Что подходит и где ограничения

- Подходит для короткого объяснения действий: выбрать должность → увидеть вакансии → открыть письмо → подтвердить тестовый отклик.
- Экспорт upstream жёстко задан как **1920×1920, 60 fps, минимум 10 секунд, без звука**. Вертикальный 9:16 требует отдельной доработки backend.
- Стеклянный эффект встроен в кружок нажатия. Стекло в самих панелях должно присутствовать в исходном интерфейсе; Showtime его не создаёт.
- Нет генерации сцен, рекламной типографики и отдельного движка анимации интерфейса. Русский текст сохраняется из входной записи.
- Повторение кадров при нормализации до 60 fps не восстанавливает пропущенное движение. Качество исходной записи остаётся важным.
- По состоянию на проверенный commit файла LICENSE нет. Условия дальнейшего распространения upstream-кода и assets не установлены; они не включены в наш репозиторий.

## Проверка обвязки

```bash
../showtime-venv/bin/python -m unittest discover -s motion/showtime -p 'test_*.py'
```

Проверяются защита исходных файлов и предыдущего экспорта, закреплённая версия и перенос путей к assets. Полный рендер требует FFmpeg и отдельно проверяется на реальной записи.

Выполнен отдельный [технический прогон на testsrc2](SMOKE_CHECK.md): экспорт и проверка прошли. Готовый ролик бота в этот прогон не входит.
